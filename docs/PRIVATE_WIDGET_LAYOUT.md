Legacy saves also retain extensions and refuse unsupported layouts.

Read and approval capabilities are owner-bound, short lived and tied to the complete source fingerprint, including microsecond timestamps. Same-origin, CSRF, session and write access checks precede mutation. A source change invalidates the review. Lost or altered acknowledgements retain the exact draft and disable repeat saves. A verified reread is required before success is displayed.

Existing uniqueness and revision checks protect first-save and update races. Isolated SQL tests exercise interleaved first saves; genuine simultaneous PostgreSQL connections remain unverified. Browser discovery is not browser acceptance.

Recovery: cancel a review to discard its authority without a write. Keep a retained draft after an uncertain save and explicitly reopen verified current settings before deciding whether to edit again. Never blindly retry. Disable the optional flag to withdraw the interface; this preserves saved records. No live migration, data cleanup or automatic rollback is required for this interface. The existing guarded encrypted restore executor now supports exact valid original layouts. Its complete transaction refuses current singleton conflicts and changed inventories and verifies every retained record after insertion; rollback protects against unrelated trigger effects. General dashboard-layout version history and real-destination recovery remain unfinished, so owner activation must await the required recovery checks.
