## Workflow

Customize Daily Brief reads the current owner's saved settings. Each of eight core sections can be moved up/down and set to Expanded, Collapsed or Hidden: due tasks, upcoming tasks, undated tasks, completed tasks, today's events, upcoming events, note titles and current projects. Missing layout settings use the existing order, with Completed tasks collapsed. Invalid, duplicate or future-version layouts fail closed instead of silently overwriting them or revealing default sections that the owner may have hidden.

The editor changes only a temporary draft. Review lists the proposed complete order and display choices. Approval saves and verifies that layout, reloads the Brief, and survives subsequent page reload/navigation. Reset to defaults is another reviewed change. Cancel changes nothing. Native disclosure toggles are temporary for this visit; saved presentation changes go through Customize Daily Brief.

Hiding a section never deletes records or changes source/account/household access. Tasks remain available in Tasks even when their Brief section is hidden. A hidden Projects section avoids its optional overview request; this is an economical display choice, not provider revocation. Typed Task/Note/Calendar workspaces neither fetch Brief layout settings nor expose this editor. The general provider panels and future domain sections still require the remaining approved configurable-widget work.

## Storage and authorization

`src/private-brief-layout.mjs` validates exactly one schema-versioned ordered entry for every supported section. Only known IDs and three presentation states are accepted. Layouts cannot contain source permissions, household grants, filters, arbitrary widgets or record mutations.

`server/private-brief-layout.mjs` extends the existing private `brief_preferences` payload only at `briefLayout`. Existing palette/density, amount privacy, navigation, sources, quiet hours and unknown extensions remain exact. Missing preferences use existing supported defaults on the first approved save. Unsupported, foreign, deleted, duplicate or malformed preference records block the operation. Existing unique active-preference protection prevents competing first saves from creating/replacing a second copy.

Read/review views and approvals expire within five minutes. HMAC base tags bind the complete current record, including unrelated preference changes, version and canonical PostgreSQL microsecond timestamps. Save requires the exact owner/session, one consumed review and mandatory fresh preflight. Optimistic storage protects the gap after authorization. Acknowledgement must have the exact next revision, payload and creation identity; a full reread must match before success. No upsert, automatic retry, access expansion or schema migration is involved.

The panel retains pending-save guards across reset, offline and session clearing, blocks new actions until settlement, and suppresses late private content/success. Uncertain saves preserve a locked copyable layout and require inspection/new review. Permission loss hides the editor. The controller includes it in cross-editor/navigation blockers without making its own permission predicate depend on its own blocked state.
