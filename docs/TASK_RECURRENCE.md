# Recurring chores and routines

Decision November 15, 2026: retain the original schedule after late completion. A Monday weekly chore finished Wednesday is next due Monday, not Wednesday.

## Prepared scheduling behavior

`src/task-recurrence.mjs` validates daily, weekly, monthly and yearly schedules with intervals 1–365 and a preserved original anchor date. Dates are civil dates between 2000 and 2100, independent of host timezone or daylight saving. It calculates the next occurrence strictly after both the current due date and completion date. Elapsed occurrences are skipped rather than creating a backlog, and the skipped count is returned for review. Early completion advances from the current scheduled occurrence rather than moving backward.

Month/year schedules clamp an unavailable date in a short month while preserving the original anchor: January31 → February28 → March31; a February29 yearly anchor returns to February29 in the next leap year. A due date outside its anchored grid, an undated task, an invalid date or a next occurrence beyond2100 stops for review instead of silently changing the rule. A bounded binary search handles decades of missed occurrences without an unbounded loop.

`src/private-recurring-task.mjs` prepares a next-occurrence draft from an existing complete, unexpired selected-task view, using the same strict copy limits as the existing task-copy flow. It retains title, section, priority, instructions and checklist titles. It omits source record IDs/history/completion flags, retains the canonical schedule and reports skipped occurrences. It never changes the source, completes a task or saves a new one. Step identities and open completion flags must be generated by the later approved insertion boundary.

## Reviewed saving prepared and verified

The owner also selected keeping the upcoming occurrence when a completed earlier occurrence is reopened. The earlier occurrence can be reopened and completed separately; this does not create another successor.

Migration007_reviewed_recurring_chore.sql prepares one invoker-rights, session-checked transaction for private fictional task records. It locks the reviewed source, checks its version and the New York review day, independently recomputes the anchored next date, preserves completed history and inserts the successor with fresh open checklist IDs. The unique series/ordinal index includes soft-deleted occurrences. Exact operation replays return the same successor without creating or repairing records; conflicting or stale requests fail. Insert/uniqueness failures roll back the completion too. No hosted execution has occurred.

The server review service uses opaque owner/context-bound, five-minute review IDs and explicit approval, checks the original snapshot again and verifies both acknowledged records against rereads. Lost acknowledgements consume the review; there is no automatic retry or fallback pair of independent writes. The optional development API exposes only the fixed atomic RPC when includeRecurringChores is explicitly enabled. It is absent by default.

The completion review can offer daily/weekly/monthly/yearly intervals for an ordinary dated task. It shows the exact next date and skipped count before the separate “Approve completion and next chore” action. An existing scheduled successor automatically uses its saved anchored rule. Historical reopening/completion explicitly says the upcoming occurrence stays scheduled. Ordinary date edits cannot move active recurring chores off their grid; title/details edits preserve the series. Series schedule changes are not implemented.
