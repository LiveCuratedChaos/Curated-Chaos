# Fictional projects/tasks routine editor

The tested autosave and recovery coordinator now has an editor mounted from the existing projects-and-tasks screen in the isolated fictional fixture. The product entry enables it only for the literal `session.fixture === true`; the controller defaults to disabled and rejects truthy aliases. Non-fictional sessions retain the accepted explicit-save editor. Only the fictional preview's static allowlist gains the new module assets; existing production/private runtime composition is unchanged.

The separate details editor supports project title/summary and task title/description/date/priority with autosave, history, guarded Undo, read-only uncertain-outcome checks and explicit reviewed resumption. It reuses the existing coordinator, client, validators and SQL-backed service. Status, completion, recurrence, checklist and project-relationship workflows remain in their existing editors; the full agreed scope remains retained.

Inputs stay mounted during saves and status updates, preserving typing/focus. The editor does not rerender unchanged state. Invalid or uncertain text requires an explicit discard confirmation before leaving; a currently saving request cannot be discarded through that control. Done flushes a valid pending edit before leaving and reloads a verified list and returns keyboard focus to a workspace action. The parent clears its old Undo receipt only after the optional editor mounts successfully, preventing a stale parent Undo button after separate autosaves. Sign-out/account lifecycle disposal cancels queued work, clears the panel and suppresses late results. No browser persistence or offline queue is introduced.
